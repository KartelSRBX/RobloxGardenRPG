# Рекомендации: Claude + Roblox Studio и дальнейшая работа

Oct 5, 2026 · по роадмапу «Сад RNG: Dungeon Survival»

## 1. Подключение Claude к Studio

### ⭐ В первую очередь: Rojo + git + Claude Code (код как файлы)
Код живёт в этой папке как обычные `.luau` файлы, Rojo синхронизирует их в Studio в реальном времени. Claude Code правит файлы напрямую, git хранит историю (в отличие от undo в Studio, которое теряется при закрытии).

Шаги:
1. Установить **Rokit** (менеджер инструментов Roblox): `irm https://raw.githubusercontent.com/rojo-rbx/rokit/main/scripts/install.ps1 | iex`
2. В папке проекта: `rokit init`, затем `rokit add rojo-rbx/rojo`, `rokit add Kampfkarren/selene`, `rokit add JohnnyMorganz/StyLua`, `rokit add UpliftGames/wally`
3. `rojo init` — создаст `default.project.json` и папку `src/`.
4. В Studio поставить плагин Rojo (`rojo plugin install`), запустить `rojo serve`, в плагине нажать Connect.
5. `git init`, первый коммит, приватный репозиторий на GitHub.
6. Добавить `CLAUDE.md` в корень: правила проекта (сервер считает все броски, mobile-first, без платного рандома) — Claude будет читать его каждую сессию.

### ⭐ Вместе с этим: Studio MCP (Claude видит и трогает сцену)
Rojo закрывает код, но не сцену (карта, модели, UI-раскладка) и не плейтест. Для этого — MCP:
- Studio: Assistant → Manage MCP Servers → Enable Studio as MCP server → Quick Connect (Claude Desktop / Claude Code).
- Использовать для: расстановки объектов, проверки иерархии, запуска плейтеста, чтения ошибок из Output.
- Правило: **скрипты меняем только через файлы (Rojo)**, через MCP — только сцену. Иначе изменения из Studio перезапишутся при синхронизации.

### Структура проекта (под Rojo)
```
src/
  shared/      → ReplicatedStorage   (Config: редкости, шансы, цены; типы; утилиты)
  server/      → ServerScriptService (DataService, SpinService, GardenService, DungeonService, ShopService)
  client/      → StarterPlayerScripts(UI-контроллеры, анимации крутилки)
  ui/          → StarterGui (если UI делается кодом)
tests/         → юнит-тесты (TestEZ / Jest-Lua)
```
Все числа баланса — в одном `shared/Config/`, чтобы менять их без правки логики.

### Линтеры и качество
- **luau-lsp** (расширение VS Code) — автодополнение и проверка типов; в начале файлов `--!strict`.
- **Selene** — линтер (`selene src`), **StyLua** — форматирование (`stylua src`).
- Попросить Claude запускать оба после каждой правки (можно хуком Claude Code).

### Библиотеки (через Wally)
- **ProfileStore** — сохранения в DataStore с защитой от дюпа и потери данных (пункт 1 роадмапа).
- Сеть: стандартные RemoteEvent с серверной валидацией хватит; при желании — ByteNet/Red.

## 2. Порядок разработки (MVP)

1. ⭐ Каркас: Rojo, git, Config, DataService на ProfileStore.
2. Крутилка (серверный RNG + таблица шансов в UI) → грядки с ростом по `os.time()` сервера → сбор урожая. **Это уже играбельный цикл — выпустить в закрытый тест.**
3. Подземелье: одна комната, 3 волны, один тип врага. Расширять только после плейтеста сада.
4. Мутации, баффы из сада, апгрейды грядок.
5. Монетизация (см. ниже), туториал, аналитика, публикация.

Совет: делать маленькими задачами («добавь SpinService по Config, с тестом»), каждая — отдельный коммит.

## 3. Монетизация — что делать первым

План в роадмапе правильный (платного рандома нет → игра доступна 6–18). Конкретно:
- ⭐ Геймпассы на старте: **+грядки**, **авто-сбор**, **x2 монеты**. Это самые понятные покупки в садовых играх.
- Developer Products: косметика грядок/питомцев, ускорение роста конкретной грядки (предсказуемый результат).
- **Premium Payouts** — включено автоматически, платит за время Premium-игроков; удерживайте игроков, это бесплатный доход.
- Rewarded/immersive ads — только с фиксированной наградой (не рандом).
- Позже: **Private Servers** по низкой цене, ивенты (лимитные семена за игру, не за Robux).
- Цены тестировать через встроенный **Price Optimization** в Creator Dashboard.

Метрики из Creator Analytics, на которые смотреть: удержание D1/D7, сессия, % дошедших до конца туториала, конверсия в покупку.

## 4. Открытые вопросы — моё мнение
- Смерть в подземелье: оставить смягчённый вариант (так в роадмапе).
- Язык: английский основной, русский — через Localization Table (автоперевод Roblox + ручная правка).
- Стиль: мультяшный low-poly — дешевле в производстве и хорошо читается на телефоне.
- Обмен между игроками: не включать в MVP.
